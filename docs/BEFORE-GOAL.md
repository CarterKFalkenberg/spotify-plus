# Before starting the build goal

Your product decisions, $0 budget and authorization for autonomous PR merges are settled. This checklist includes both your account setup and the repository work I will finish. Exact commands and credential locations are in [SETUP.md](SETUP.md).

1. **Skills and agent instructions — complete locally.** Installed Matt Pocock's current `grill-with-docs`, `wayfinder`, and `code-review`, plus their five supporting skills; created `pr-writing`; completed `AGENTS.md`, [skill routing](agents/skills.md), GitHub tracker/domain conventions and [shared milestone acceptance](agents/acceptance.md). Validated all nine entrypoints, bundled references and upstream provenance. Saved on the planning branch; publishing and merging this setup remains step 3.
2. **GitHub authentication — you.** Sign in with `gh auth login --hostname github.com --git-protocol https --web --scopes repo,workflow`, then `gh auth setup-git`. The connector account has repository admin access; the CLI is not signed in. This enables branch pushes, workflow changes, issues and PR merges under your account.
3. **Repository and CI setup — me.** Review and merge the bootstrap PR, then require PRs, passing `verify`, an up-to-date branch and resolved conversations on main, with zero required human approvals. Keep main as the clean tracking checkout and do all edits in worktrees. Each build milestone gets a reviewed PR that I merge myself after verification.
4. **Local tooling and actual permissions — us.** Verify Node 24, Deno, Supabase CLI, Wrangler, GitHub CLI, Codex access and a running Docker daemon. Verify worktree/Git writes, dependency downloads, test browsers and deployment commands can run under the session's permission policy. Written authorization does not itself grant tool or account access; resolve actual permission prompts before leaving the build unattended.
5. **Free hosting accounts — you.** Create a Supabase Free project and Cloudflare Workers Free Worker; obtain the HTTPS URL, IDs, Supabase management token and database password, and complete Wrangler browser login. No paid upgrades or domain purchase.
6. **Spotify app — you.** Create the developer app, allowlist your account, register both exact callback URLs, and provide the client ID and expected Spotify user ID. PKCE requires no client secret.
7. **Private configuration — us.** Initialize ignored `.local` files and enter the identifiers/credentials there. Repository/merge authorization is already recorded. Confirm the remaining scope for dependency installation, deployments to the configured free targets and disposable Spotify test playlists; store no secrets in Git or chat.
8. **Spotify consent and preflight — us.** You complete the connection helper's browser consent; I check account/target access and run `./scripts/build --check`. Live API and deployment proof is the first build milestone, not something preflight already proves.
9. **Planning readiness — me.** Use the requested planning skills against the accepted brief, close any remaining implementation-critical questions, and record milestones/acceptance in the repository and GitHub issues where useful. Avoid reopening decisions you already made.
10. **Start the goal — you.** Tell this chat to start the autonomous build once the above is ready. Keep the Mac awake and online. No goal is running yet. Real phone usability and personal tagging-speed acceptance remain your final checks after software PRs merge.
